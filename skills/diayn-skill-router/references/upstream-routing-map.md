# Upstream Routing Map

DIAYN is the multi-session control plane. `third_party/agent-skills` is an optional engineering method library. DIAYN authority wins on role, lane, status, permissions, evidence, and Owner acceptance.

| DIAYN context | Upstream skills to consider |
| --- | --- |
| Fuzzy idea during init | `interview-me`, `idea-refine`, `spec-driven-development` |
| Controller planning | `planning-and-task-breakdown`, `context-engineering`, `documentation-and-adrs` |
| Backend lane execution | `incremental-implementation`, `test-driven-development`, `api-and-interface-design`, `debugging-and-error-recovery`, `security-and-hardening` |
| Frontend lane execution | `incremental-implementation`, `frontend-ui-engineering`, `browser-testing-with-devtools`, `test-driven-development`, `performance-optimization` |
| Review session | `code-review-and-quality`, `doubt-driven-development`, `security-and-hardening` |
| Integration review | `code-review-and-quality`, `api-and-interface-design`, `ci-cd-and-automation`, `git-workflow-and-versioning` |
| Scaffold upgrade | `deprecation-and-migration`, `documentation-and-adrs`, `context-engineering` |
| Release readiness | `shipping-and-launch`, `ci-cd-and-automation`, `security-and-hardening`, `performance-optimization` |

Do not copy upstream instructions into DIAYN protocol files. Route explicitly, read narrowly, and cite the routing decision in the active workflow report when relevant.
