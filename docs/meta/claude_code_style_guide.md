# Claude Code 代码规范细则

> 本文件定义代码注释原则、Python docstring 模板与注释边界。
> 读取时机：当任务涉及新增代码、新增公开函数或修改复杂逻辑时，按需读取。

## 1. 代码书写、注释与函数说明规则

### 1.1 基本要求

- 新增代码应包含必要注释，重点解释 **为什么这样做**、**关键约束是什么**、**哪些设计选择不能随意改**，不要只重复代码表面行为。
- 新增或直接改动的公开函数、类、公开模块，以及包含复杂逻辑、状态变化、边界处理或副作用的内部函数，必须补充清晰说明。
- 说明应覆盖：作用、输入、输出、关键副作用、异常或失败行为、重要约束。
- 简单的私有 helper 函数也应通过类型标注、清晰命名或一句话 docstring 表达输入、输出和作用；不得为了满足注释要求堆砌无意义注释。
- 若项目已有统一 docstring 风格，则遵循项目现有风格；若没有统一风格，Python 默认使用简洁的 Google-style docstring。

### 1.2 Python 函数 docstring 模板

```python
def example_function(input_path: str, max_items: int) -> list[str]:
    """从指定路径读取最多 max_items 条记录。

    Args:
        input_path: 输入文件路径。
        max_items: 最多读取的记录数量。

    Returns:
        读取到的记录列表。

    Raises:
        FileNotFoundError: 当 input_path 不存在时抛出。
    """
```

### 1.3 注释边界

- 不为了满足“有注释”而堆砌无意义注释。
- 不在每一行都写注释。
- 对复杂逻辑、边界判断、状态转换、数据格式约束、兼容性处理、临时方案、性能或安全相关代码，应优先写注释。
- 如果某个实现是临时方案，必须标注原因、影响范围和后续建议，不得留下没有解释的 TODO。
