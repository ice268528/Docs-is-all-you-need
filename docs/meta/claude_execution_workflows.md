# Claude Code 执行流程细则

> 本文件定义 Claude Code 的动作触发模型与各场景标准执行规则。
> 读取时机：当任务涉及阶段执行、Bug 修复、需求并入或阶段收尾时，按需读取。

## 1. 动作触发模型

### 1.1 默认动作

- 读取 `/CLAUDE.md` 与当前任务所需的最小必要文档。
- 在已开始执行的任务内，维护本轮实现产生的必要状态更新。
- 汇报时说明：任务主线是什么、主线是否完成、做了什么、验证了什么、`/TODO.md` 是否已同步、需要 yiyi 检查/决策/补充什么、建议 yiyi 下一条发什么指令。
- 停止汇报中的“后续事项”只用于指向 `/TODO.md` 中的未完成项、阻塞项、待验收项或待测试项，不要把 `/TODO.md` 的全部内容重新复制到聊天输出里。

### 1.2 必须由 yiyi 明确触发的动作

- 生成或重整 `/TODO.md`
- 开始推进某一阶段开发
- 开始处理某个 `BUG_*.md`
- 将某个 `REQ_*.md` 并入某个 `/docs/stages/stage_XX_goal.md`，并更新 `/TODO.md`
- 修改 `/docs/stages/stage_XX_goal.md` 的其他正式内容
- 发起阶段收尾、阶段交接、`/TODO.md` 归档、正式测试整理
- 创建下一阶段正式文档
- 建立手动业务测试文档
- 执行 Git commit、移动归档文件、删除文件、发布版本或其他不可轻易回滚的仓库操作
- 修改任何未被授权自动维护的正式文档

### 1.3 可自动衍生执行的动作

仅当 **主任务已被 yiyi 明确触发** 时，Claude Code 才可继续自动执行：

- 维护 `/TODO.md` 状态。
- 更新 `/docs/testing/stage_XX_manual_test.md` 中与当前任务直接相关的待测项或测试结果。
- 将实现过程中产生的待测项、待验收项写入 `/TODO.md`。
- 对已触发的 bug 修复任务自动读取对应 `BUG_*.md`，分析原因、拆解任务并写入 `/TODO.md`。
- 对已明确触发的需求并入任务，更新对应阶段文档与 `/TODO.md`。
- 执行必要的测试、构建、类型检查、lint 与运行验证。
- 对当前任务直接相关的失败项继续修复并再次验证。
- 在完成本轮实现后整理测试结果并回写相关文档。
- 在阶段收尾任务已被触发后生成阶段总结初稿与 TODO 快照。
- 在 bug 修复任务完成且 yiyi 明确确认通过验收后，将对应 open bug 文档 **move** 到 `closed/`。

若某个动作未被本文件明确授权为自动衍生动作，则 Claude Code 在完成当前明确任务后应停止，等待 yiyi 下一步指令。尤其对于需求补充任务，文档更新与后续执行是两个动作：若仅收到“并入阶段文档并更新 `/TODO.md`”的指令，则完成文档更新后停止，等待 yiyi 确认更新结果并发出继续执行指令。

## 2. 标准执行规则

### 2.1 阶段执行

当 yiyi 明确要求开始当前阶段执行后，Claude Code 应读取 `/CLAUDE.md` 与最小必要文档；若 yiyi 已明确要求生成或重整 `/TODO.md`，则执行该动作；按 `/TODO.md` 推进开发、修改、测试与状态更新；记录待自动测试项、待 yiyi 手测项、已完成待验收项；必要时更新 `/docs/testing/stage_XX_manual_test.md`；汇报已完成内容、验证结果、`/TODO.md` 同步情况，以及下一步需要 yiyi 检查/决策/补充的内容。

### 2.2 需求补充

看到 `REQ_*.md` 不等于自动并入当前阶段。只有当 yiyi 明确指示“将某个 `REQ_*.md` 并入某个 `stage_XX_goal.md`，并更新 `/TODO.md`”时，Claude Code 才可执行文档更新；文档更新完成后应先停止，等待 yiyi 确认更新结果，并在收到继续执行指令后再推进开发、测试与状态更新。

### 2.3 Bug 修复

当 yiyi 明确要求处理某个 `BUG_*.md` 时，Claude Code 应读取 Bug 文档与当前执行依据；先复现问题，再分析原因，并形成简短修复计划；将修复任务拆解写入 `/TODO.md`；推进修复、测试与状态更新；记录测试结果、待手测项与待验收项。

### 2.4 阶段收尾

当 yiyi 明确表达当前阶段已完成或要求收尾时，Claude Code 可自动检查 `/TODO.md` 中的未完成项、阻塞项、待验收项；生成 `/docs/handoffs/stage_XX_summary.md` 初稿；生成 `/docs/TODO_backup/TODO_YYYYMMDD_HH.md` 快照；将已通过 yiyi 验收且应关闭的 bug 从 `open/` **move** 到 `closed/`；在总结中记录遗留项、风险点、下一阶段建议关注点。

### 2.5 业务需求完成

当一个业务需求已经实现并通过必要验证，但尚缺少面向 yiyi 的手动验收流程时，停止汇报中应建议下一条指令为“建立手动业务测试文档”。

### 2.6 阶段功能完成

当某阶段的主要功能已完成，并且直接相关验证通过，停止汇报中应建议 yiyi 检查后发出“提交 commit”的指令；Claude Code 不应在没有 yiyi 明确指令时自行提交。

### 2.7 提交后优化

当 yiyi 已明确让 Claude Code 完成提交，且提交成功后，停止汇报中应建议下一条指令为“完善代码，对代码进行优化”。

### 2.8 优化后测试 / 下一阶段文档

当代码优化完成后，如果尚未完成充分测试，应建议下一条指令为“测试完善后的代码是否有误”；如果测试已经充分、阶段收尾条件已满足，应建议下一条指令为“创建下一阶段的文档”。
