# Agent 执行流程细则

> 本文件定义 Code Agent 的动作触发模型与标准执行规则。

## 1. 默认动作

Code Agent 在每轮实现、修改、修复、测试、归档或文档维护前，应默认：

- 读取 `AGENTS.md`。
- 读取当前任务所需的最小必要文档。
- 明确任务主线、成功标准和验证方式。
- 在已开始的任务内维护必要状态更新。
- 停止时说明主线、完成情况、验证情况、`TODO.md` 同步情况和下一步建议。

## 2. 必须由 Owner 明确触发的动作

- 生成或重整 `TODO.md`。
- 开始推进某一阶段开发。
- 开始处理某个 `BUG_*.md`。
- 将某个 `REQ_*.md` 并入某个 `stage_XX_goal.md` 并更新 `TODO.md`。
- 修改阶段目标、验收标准、项目边界或实现约束。
- 发起阶段收尾、阶段交接、TODO 归档、正式测试整理。
- 创建下一阶段正式文档。
- 执行 Git commit、移动归档文件、删除文件、发布版本或其他不可轻易回滚的仓库操作。
- 修改任何未被授权自动维护的正式文档。

## 3. 可自动衍生执行的动作

仅当主任务已被 Owner 明确触发时，Code Agent 才可自动继续：

- 维护 `TODO.md` 状态。
- 更新 `docs/testing/stage_XX_manual_test.md` 中与当前任务直接相关的待测项或测试结果。
- 将实现过程中产生的待测项、待验收项写入 `TODO.md`。
- 对已触发的 Bug 修复任务读取对应 `BUG_*.md`，复现、分析、修复、验证。
- 对已触发的需求并入任务，按 Owner 指定范围更新阶段文档与 `TODO.md`。
- 执行必要的测试、构建、类型检查、lint 与运行验证。
- 对当前任务直接相关的失败项继续修复并再次验证。
- 在阶段收尾任务已被触发后生成阶段总结初稿与 TODO 快照。

若某个动作未被明确授权，Code Agent 在完成当前明确任务后应停止，等待 Owner 下一步指令。

## 4. 标准执行规则

### 4.1 阶段执行

当 Owner 明确要求开始当前阶段执行后，Code Agent 应：

1. 读取 `AGENTS.md`、阶段文档、实现约束和 `TODO.md`。
2. 若 Owner 要求生成或重整 `TODO.md`，先完成该动作。
3. 按 `TODO.md` 推进开发、修改、测试与状态更新。
4. 记录待自动测试项、待手测项、已完成待验收项。
5. 必要时更新当前阶段手动测试文档。
6. 汇报完成内容、验证结果、TODO 同步情况和需要 Owner 决策的内容。

### 4.2 需求补充

看到 `REQ_*.md` 不等于自动并入当前阶段。只有当 Owner 明确指示“将某个
`REQ_*.md` 并入某个 `stage_XX_goal.md` 并更新 `TODO.md`”时，Code Agent 才可执行文档更新。

文档更新完成后，若未收到继续执行指令，应停止等待 Owner 确认。

### 4.3 Bug 修复

当 Owner 明确要求处理某个 `BUG_*.md` 时，Code Agent 应：

1. 读取 Bug 文档与当前执行依据。
2. 尽可能先复现问题。
3. 分析原因并形成简短修复计划。
4. 将修复任务拆解写入 `TODO.md`。
5. 推进修复、测试与状态更新。
6. 记录验证结果、待手测项与待验收项。

### 4.4 阶段收尾

当 Owner 明确表达当前阶段已完成或要求收尾时，Code Agent 可：

- 检查 `TODO.md` 中的未完成项、阻塞项、待验收项。
- 生成 `docs/handoffs/stage_XX_summary.md` 初稿。
- 生成 `docs/TODO_backup/TODO_YYYYMMDD_HH.md` 快照。
- 在 Bug 已通过 Owner 验收且获得明确触发后，将对应 open Bug 文档移动到 `closed/`。
- 在总结中记录遗留项、风险点和下一阶段建议关注点。

### 4.5 完成与提交

- 未验证前，不应建议提交。
- 阶段主要功能完成、直接相关验证通过、没有明显阻塞时，可建议 Owner 检查后发出提交指令。
- Code Agent 不应在没有 Owner 明确指令时自行提交。
