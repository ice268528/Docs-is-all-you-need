# Claude Plugin Runtime Acceptance

This checklist verifies the standard Claude Code plugin / marketplace path
after the plugin namespace was shortened to `diayn`.

Do not use project-local `/diayn-*` success as evidence for plugin mode.

## Record Environment

Record:

```text
Claude Code version:
Docs-is-all-you-need commit:
OS:
Install path tested:
```

Get the Claude Code version:

```powershell
claude --version
```

## Static Validation

Run from the repository root:

```powershell
claude plugin validate .claude-plugin\plugin.json
claude plugin validate .claude-plugin\marketplace.json
claude plugin validate plugins\docs-is-all-you-need\.claude-plugin\plugin.json
claude plugin validate plugins\docs-is-all-you-need\.claude-plugin\marketplace.json
node maintainers\scripts\validate_diayn_public_skill_surface.js
node maintainers\scripts\validate_diayn_dependency_skills.js
node maintainers\scripts\validate_diayn_claude_project_local_package.js
node maintainers\scripts\validate_diayn_alpha_package.js
git diff --check
```

Expected static result:

```text
plugin.json name = diayn
plugin command adapters expose /diayn:<short-command> and invoke diayn:diayn-*
plugin command adapters declare platform: claude-code and entry_file: CLAUDE.md
project-local command adapters invoke local diayn-* skill ids
repository-root skills/ contains the 12 workflow skills
root plugin manifest explicitly registers bundled dependency skills only
```

The root plugin manifest points at
`plugins/docs-is-all-you-need/dependency-skills/agent-skills/skills` so
dependency skills are native-callable. The 12 DIAYN workflow skills come from
the repository-root `skills/` directory that Claude Code discovers for the
plugin. The project-local fallback remains a separate installation path and is
not used as the root plugin skills root.

This is not a command-only plugin. `/plugin details diayn` may show DIAYN
workflow skills and bundled dependency skills. The acceptance target is no
duplicate registration, not an empty Skills section.

## Local Plugin-Dir Runtime Verification

Use a clean demo repository. Start Claude Code with the repository-root plugin:

```powershell
claude --plugin-dir <Docs-is-all-you-need repo path>
```

Verify what commands Claude Code actually exposes:

```text
/diayn:init
/diayn:plan
/diayn:backend
```

Check whether the old long plugin command names are visible:

```text
/diayn:diayn-init
/diayn:diayn-plan
/diayn:diayn-backend
```

Expected current result:

```text
/diayn:<short-command> should be visible if Claude Code derives the namespace from plugin.json name.
/diayn:diayn-* workflow skill entries may be visible as installed DIAYN workflow skills, but each should appear once.
/diayn:<dependency-skill> entries may be visible as bundled native-callable dependency skills, but each should appear once.
/diayn-* bare commands may appear only if a separate project-local fallback is installed; they must not appear many times.
```

Invoke the first command with a vague idea:

```text
/diayn:init "I have a vague project idea; ask me the missing questions before changing files."
```

Acceptance checks:

```text
The command adapter invokes native Skill tool skill: "diayn:diayn-init".
The command adapter declares platform: claude-code and entry_file: CLAUDE.md.
The skill follows progressive disclosure.
The skill does not silently mutate Owner requirements.
OwnerGate / Unknown handling appears for unclear requirements.
Dependency routing uses DIAYN-managed dependency skills only when relevant.
Dependency skills are installed/native-callable, not text-only references.
The init result creates or updates CLAUDE.md.
The init result does not create AGENTS.md by default.
.diayn/scaffold_version.md records platform = claude-code and entry_file = CLAUDE.md.
The init result creates .diayn/dependency-routing/upstream-routing-map.md for later workflow dependency-skill routing.
docs/project/harness_audit_report.md records the selected entry file and why AGENTS.md was not generated by default.
```

If Claude exposes `/diayn-*` bare commands in plugin mode, record it only as
observed behavior for the tested Claude Code version. Do not treat it as a
cross-version guarantee.

## Inner Plugin Candidate Runtime Verification

Use only for focused plugin-dir command-adapter debugging:

```powershell
claude --plugin-dir <Docs-is-all-you-need repo path>\plugins\docs-is-all-you-need
```

Repeat the command visibility and `/diayn:init` workflow-entry checks.

Do not enable this inner candidate together with the repository-root plugin
when judging duplicate `/diayn` autocomplete entries. That is a deliberately
duplicated local-debug setup, not the standard marketplace-style install.

Do not use this inner candidate to prove the standard plugin's bundled
dependency-skill inventory. The repository-root plugin is the authoritative
marketplace-style surface because it combines repository-root workflow skills
with the manifest-registered DIAYN-managed dependency skills.

## Marketplace-Style Runtime Verification

If testing GitHub marketplace-style install:

```text
/plugin marketplace add ice268528/Docs-is-all-you-need
/plugin install diayn@diayn-local-alpha
```

Record:

```text
Whether install succeeds.
The actual marketplace name Claude Code assigns.
The actual visible command names.
Whether /diayn:init invokes skill: "diayn:diayn-init".
Whether dependency skills are native-visible.
Whether bare /diayn-* appears, if at all.
Whether /plugin details diayn shows workflow/dependency skills without duplicate names.
Whether /diayn autocomplete shows the 12 /diayn:* commands without repeated copies.
```

DIAYN does not claim Anthropic official marketplace listing unless that has
separately happened and been verified.

## Project-Local Fallback Verification

Project-local fallback is a separate path. It installs into a target project's
`.claude/` and `.diayn/` directories and should provide bare commands:

```text
/diayn-init
/diayn-plan
/diayn-backend
```

Static package validation:

```powershell
node maintainers\scripts\validate_diayn_claude_project_local_package.js
```

Acceptance checks:

```text
Project-local commands invoke local skill ids such as "diayn-init".
Project-local commands do not invoke plugin ids such as "diayn:diayn-init".
Project-local init creates or updates CLAUDE.md and does not create AGENTS.md by default.
Project-local success is not described as plugin/marketplace success.
Codex and generic scaffold files are not changed by this verification.
```

## Agent-Skills Reference Check

DIAYN primarily follows the `agent-skills` pattern for Claude plugin structure:

```text
.claude-plugin/plugin.json declares commands and skills.
.claude/commands/*.md are thin command adapters.
skills/*/SKILL.md holds the real skill instructions.
```

Reference project runtime behavior can be compared separately, but do not copy
`superpowers` behavior mechanically because its current structure relies more on
default directory discovery and bootstrap behavior.
